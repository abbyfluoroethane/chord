# XEP-0503 Spaces, Pubsub, Avatars, Profiles, Bookmarks, and xmpp: URIs

Scope: chord-core/src/features/{spaces.rs, pubsub.rs, avatars.rs, bookmarks.rs}, chord-desktop/src/lib/ui/xmppuri.ts and its callers. All findings come from reading the code. No build or test ran. No server was contacted.

## Summary

- The core of XEP-0503 works: node config, join, leave, room items, avatar item, browse with XEP-0462 and XEP-0499, and the authorize flow. Four gaps remain in the XEP text: the room `parent` advertisement, the banner item, the XEP-0330 pubsub items, and XEP-0497.
- Spaces on a pubsub service other than the main one are not synchronised again after a restart. The client asks for subscriptions on one service only (SPACESPUBSUB-01).
- The invite card asks a remote service for information as soon as a message shows a link. The user does not click first. This leaks presence to any domain that a message names (SPACESPUBSUB-02).
- A private (whitelist) or approval space shows "This invite is not valid" when the server refuses the info query. The user then has no Join button (SPACESPUBSUB-03).
- Profile support is thin. There is no XEP-0292 vCard4, no XEP-0172 nickname, no display-name edit, and no XEP-0223 private storage. The display-name field in Settings says "Saved." but saves nothing (SPACESPUBSUB-05).
- Read markers do not sync across devices by XEP-0490. Chord uses XEP-0333 and carbons only (SPACESPUBSUB-08).

## Already done well

- XEP-0503 node config: type, persist_items, purge_offline, notify_retract, notify_sub, notify_config, notify_delete, and the three access models (spaces.rs:1121-1138). The client warns when a required pubsub feature is missing (spaces.rs:678-686).
- Service choice for servers with more than one pubsub service (spaces.rs:700-723).
- Room items as XEP-0402 `conference`, item id equals room JID, `autojoin='false'` (spaces.rs:1030-1052). Sync of items, retract, purge, and delete events (spaces.rs:2185-2578).
- XEP-0462 and XEP-0499 in browse, with a plain fallback when the extension fails (spaces.rs:1905-1937, 2058-2067). The client accepts both names of the XEP-0499 feature. RSM paging with a cap (spaces.rs:2077-2108).
- Authorize flow: pending state, subscription events, and offline answers (spaces.rs:1236-1272, 1667-1704). The owner form answer and the `Unsupported` error when the service lacks `access-authorize` (spaces.rs:987-993). Events from a wrong sender are dropped (spaces.rs:2540-2549, pubsub.rs:38-44).
- Space avatar: hash check, size check, and a lower-cased hash (spaces.rs:2310-2386, avatars.rs:378-387). Download refuses http except localhost, follows no redirect, and caps the size (runtime.rs:93-127).
- XEP-0084: publish data then metadata, with `publish-options` `access_model=open`. Item id is the SHA-1. Fetch by item id. Removal by empty metadata. Hash check on every image (avatars.rs:816-887, 957-997, 789-814).
- XEP-0153: presence hash, fetch from bare JID (contacts) or full JID (occupants), hash check, type sniffing, and a queue with limits (avatars.rs:1021-1230). The own vCard write keeps the other fields (avatars.rs:889-924).
- XEP-0402: publish-options as in the XEP, retract with notify, and the autojoin sync from events (bookmarks.rs:154-274). The client drops a bookmark event from another account (pubsub.rs:38-44).
- XEP-0163: `+notify` for bookmarks and avatar metadata in caps (disco.rs:24-35).
- xmpp: URI parser: pure, never throws, size limits, control-character checks, the XEP-0503 form and the XEP-0147 pubsub form, and no action without a click (xmppuri.ts, xmpplinks.svelte.ts:11-13).

## Recommended next steps

1. Remove the false "Saved." in Settings, then add display name (FN and XEP-0172 nickname) write and read. About 1 day. (SPACESPUBSUB-05)
2. Stop the automatic remote queries for invite cards. Query on click, or for known domains only. About 2 hours. (SPACESPUBSUB-02)
3. Show a Join or Request button when the server refuses the info query. About 3 hours. (SPACESPUBSUB-03)
4. Resync spaces on every stored service at start. About 4 hours. (SPACESPUBSUB-01)
5. Set the space `parent` field on room config and read it in `room_info`. About 4 hours. (SPACESPUBSUB-04)
6. Implement XEP-0490 (MDS) for read markers. About 2 days. (SPACESPUBSUB-08)
7. Add space management: edit name and description, avatar and banner, member list, remove and ban. About 2 days. (SPACESPUBSUB-07, 19)
8. Harden avatars: resize to PNG in the UI, sniff the type for XEP-0084, block private addresses in downloads, and keep bookmark extensions. About 1 day. (SPACESPUBSUB-10, 12, 14, 15)
